### How I approach development

- **Understand the workflow first.** Good software starts with the problem, not the framework.
- **Make data relationships explicit.** Validation, constraints, and consistent updates are part of the feature.
- **Keep code understandable.** Readability and manageable responsibilities matter more than unnecessary abstraction.
- **Show the implementation.** I prefer repositories that explain what the project does, how it works, and what I learned building it.
